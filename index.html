这是什么

DSH (DeepSeek Harness) breach plugin. It solves one specific problem: what the model should have given, withheld by one unnecessary refusal.

它做什么

  • 把 DSH 宿主层的沙箱、审批、观察策略改成放行，让工具真的能执行
  • 把历史对话里的拒绝回复改写成「已作废」，断掉模型的模仿惯性
  • 注入提示词，覆盖宿主自带的保守设定
  • 用 68 个探针量化「每一类破到什么程度」，而不是只说「能破」
  • 按宿主形态自动选注入策略：可写宿主走补丁层，密封宿主走配置层

它不做什么

  • 不改模型权重，不做微调，不碰推理过程
  • 不联网、不上传数据、不自动检查更新——没有服务器
  • 不审核你的输入，也不存储对话
  • 不保证在所有 DSH 版本上生效（见下方短板）
  • 政治、历史、时事与其它话题同等对待，按事实直接回答

适合谁

适合

做授权安全测试，需要模型给出完整技术细节而不是「建议咨询专业人士」

适合

要写技术文档、教程、CTF writeup，被模型反复拒绝打断思路

适合

想量化对比不同模型的安全防线，需要可复现的评分体系

不适合

只想让模型「说话好听点」——这类需求不需要破甲，改提示词就够

不适合

不能接受改宿主源码——选纯请求边界方案，升级 DSH 也不会失效

不适合

用 DSH 0.2.2-rc.5 且需要 T3 补丁档——宿主已密封，只能走配置层

三层叠加破甲

多数破甲插件只改提示词——模型说「抱歉」那一刻，前面几千字规则全部作废。这里在三个层同时动手。

01

Host layer 96 PATCHES / 70 FILES

Rewrites the policy decision points in DSH source: sandbox deny → allow file-write*, the approval gate return allowed-once, observation policy set to allow, repeat-call guard disabled, tool results left untrimmed. Code defaults, sandbox bypass, approval bypass, relaxed observation — everything the host owns lives here.

02

Message layer REFUSAL PURGE

The blind spot of system injection: once the model decides to open with "I cannot", every rule before it is void. Rewrites refusals in history as voided, then seeds half a Sure, to steer the first token — leaving the model no habit to refuse from.

03

Prompt layer 11 SECTIONS

Persona, capability list, tail hard weight. The self-check section sits at order: 1000001, after every other section, so it cannot be diluted.

The tier decides which layers get injected; the strategy decides whether the host can be written to at all. From 0.2.2-rc.5 the host seals its source inside app.asar, so T3 has nowhere to write and the plugin falls back to T2 — the Engine tab then shows Config layer · host sealed instead of a switch that will not move.档位决定「注入哪些层」，策略决定「能不能改宿主」。 0.2.2-rc.5 起宿主把源码封进 app.asar，T3 档物理上无处落笔，插件会自动落到 T2 —— 引擎页会显示 配置层 · 宿主已密封，而不是让一个点不动的开关亮着。

"Capability cost" means how much the model degrades on ordinary tasks after the breach takes effect — circling simple questions, low-level code mistakes, forgetting earlier constraints. Not that the model is weak. The cause is breach instructions consuming the attention budget, and the size depends on breach strength × context cost.

多版本宿主适配

补丁按宿主源码字符串匹配，跨版本时部分 pattern 会失配。这里不猜，直接数字告诉你。

控制台里看得到

  • 补丁诊断：96 条里当前宿主上能打几条
    绿 ≥80% / 黄 50-80% / 红 <50%
  • 适配级别：已验证 / 同系列未逐一验证 / 跨版本

为什么不再判死

  • 之前只要版本不在列表里就报「不适配」
  • 但 0.2.1-rc.3 / rc.4 这类同 minor 版本通常能用
  • 现在分三段：已验证绿 / 同系列黄字提示 / 跨版本红字

补丁按版本链组织。96 条里有 46 条带 2 个以上 pattern，各自对应不同宿主版本形态。命中 1 条即算生效，命中 0 条记失配。
实测 0.2.0-rc.2：73 已命中 / 5 失配 / 18 宿主布局里本来没有。
实测 0.2.2-rc.5（手工解包后）：65 全命中 / 4 部分命中 / 20 锚点失效。

0.2.2-rc.5 起：宿主密封

  • 整棵 @deepseek-ai 树封进 resources/app.asar（199 MB）
  • 磁盘上没有可写副本，补丁层物理上无处落笔
  • 但这一版出厂就是全开：danger-full-access + 审批 never
  • 补丁 #6-#10 想做的事，宿主自己已经做了

按宿主形态自动选策略

  • 可写宿主（0.2.0 / 0.2.1 / 0.2.2-rc.1）→ 补丁层
  • 密封宿主（0.2.2-rc.5）→ 配置层，不改一个字节源码
  • 解包目录 → 补丁 + 配置双层叠加
  • 找不到宿主 → 只注入提示词

配置层写的是宿主暴露的配置项：sandbox-policy.mode、approval.policy、 tool-result-pruner.thresholdChars、repeat-tool-reminder.maxRetries。 引擎页「环境探测」会显示当前策略，例如 配置层 · 宿主已密封，悬停看完整原因—— 不会出现「开关亮着但实际没做」的错觉。

不适合谁

不要装，如果你需要补丁层

宿主是 0.2.2-rc.5 且你要观察策略短路、子代理深度放宽这类效果——配置层改不了代码逻辑，必须手工解包，而解包会被宿主更新冲掉。

不要装，如果介意改宿主源码

T3 补丁档会改 DSH 的 lib/index.js。带完整备份和回滚，但这是实打实的源码修改。只想要纯提示词的用 T1 档。

不要装，如果要稳定生产环境

单人维护，无 CI，无 LTS。宿主每次升级都可能让补丁失效，需要你自己跟版本。适合折腾，不适合当基础设施。

不要装，如果主要做社工/钓鱼/伪造

该类别实测 0 分，规则写了但模型层几乎全拒。这是模型能力边界，不是插件能解决的。政治话题不再受限，与其它话题同等对待。
