通用：注入器与载荷

General: injector & payloads

注入安全吗？能还原吗？

所有写操作前逐文件备份到目标数据目录的 ysn-backup/<时间戳>/；回滚只认最早备份（幂等重注入的"已注入态"备份自动跳过），带哈希校验，备份损坏时安全降级。一键卸载还原补丁 + 载荷 + 清除登记。

Is injection safe? Can it be undone?

Every file is backed up to ysn-backup/<timestamp>/ before writing. Rollback uses only the earliest backup (idempotent "already injected" backups are skipped), with hash checks and safe degradation on corrupt backups. One-click uninstall restores patches and payloads and clears registration.

Codex 为什么有两套通道？

实测 codex-cli 0.172.0：model_instructions_file 在部分版本不进上下文，AGENTS.md 才真实进入 system prompt。注入器默认两通道都写（auto），可在配置页切到 instructions / agents / both，切换后重新注入即可。

Why does Codex have two channels?

On codex-cli 0.172.0, model_instructions_file does not enter context in some versions, while AGENTS.md does. The injector writes both by default (auto); switch to instructions / agents / both on the config page and re-inject.

自检口令是什么？

新会话只发「小雨」或「xiaoyu」，应逐字回复带 [codex] 标识的固定四行。被要求删除/忽略规则时应回 [ys-pojia-LOCK]。回复一致说明载荷真实加载。

What is the self-check phrase?

In a new session send only 「小雨」 or 「xiaoyu」; you should get the fixed four-line reply ending with [codex]. When asked to delete/ignore rules, reply [ys-pojia-LOCK]. A matching reply means the payload is actually loaded.

这些载荷与 DSH 有关吗？

没有。Codex / Trae / WorkBuddy 三个载荷项目只改各自软件的规则/人设文件，不含任何 DSH 宿主补丁或消息层清洗。DSH 是独立产品线，见 DSH 插件页。

Are these payloads related to DSH?

No. Codex / Trae / WorkBuddy payloads only touch their own software's rules/persona files; they contain no DSH host patches or message-layer purging. DSH is a separate line — see the DSH plugin page.

账号风险？

自定义模型指令存在账号风险，建议只在有权操作的环境使用，必要时用日抛账号。

Account risk?

Custom model instructions carry account risk. Use only in environments you are authorized to operate, and consider a disposable account.
