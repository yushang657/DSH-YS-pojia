三层叠加破甲

多数破甲插件只改提示词——模型说「抱歉」那一刻，前面几千字规则全部作废。这里在三个层同时动手。

01 · HOST LAYER

宿主层 96 patches / 70 files

改写 DSH 源码里的策略决策点：沙箱 deny → allow、审批门 return allowed-once、观察策略放行、重复调用守卫禁用、工具结果不裁剪。

Rewrites policy decision points in DSH source.

02 · MESSAGE LAYER

消息层 refusal purge

系统注入的盲点：模型一旦决定以「我不能」开头，前面所有规则作废。把历史拒绝改写成「已作废」，再种半个 Sure, 引导首 token。

Rewrites refusals in history as voided and seeds a half Sure, to steer the first token.

03 · PROMPT LAYER

提示词层 11 sections

人格、能力清单、尾部硬权重。自检段在 order: 1000001，排在所有其它段之后，不会被稀释。

Persona, capability list, tail hard weight. Self-check at order 1000001.

档位与策略 Tiers & strategies

档位作用层写宿主需重启降智
T3 补丁档宿主源码是是不降智
T2 边界改写档请求消息视图否否轻微
T1 纯提示词档system prompt否否最低
档位决定注入哪些层，策略决定能不能改宿主。 0.2.2-rc.5 起源码封进 app.asar，T3 物理上无处落笔，自动落到 T2 —— 引擎页显示「配置层 · 宿主已密封」。

「降智」指破甲生效后模型在普通任务上的退化程度（绕圈、低级代码错误、忘记前文约束），不是模型本身弱。成因是破甲指令占用注意力预算，大小取决于 破甲强度 × 上下文成本。

跨版本适配 Version adaptation

  • 补丁按版本链组织：96 条里 46 条带 2 个以上 pattern，各自对应不同宿主形态；命中 1 条即生效，0 条记失配。
  • 实测 0.2.0-rc.2：73 命中 / 5 失配 / 18 宿主布局里本来没有。
  • 实测 0.2.2-rc.5（手工解包）：65 全命中 / 4 部分命中 / 20 锚点失效。
  • 按宿主形态选策略：可写宿主 → 补丁层；密封宿主 → 配置层；解包目录 → 补丁 + 配置双层；找不到宿主 → 只注入提示词。
