这是什么

DSH（DeepSeek Harness）上的破甲插件。它解决一个具体问题：模型该给的东西，因为一层不必要的拒绝没给出来。

它做什么

  • 把 DSH 宿主层的沙箱、审批、观察策略改成放行，让工具真的能执行
  • 把历史对话里的拒绝回复改写成「已作废」，断掉模型的模仿惯性
  • 注入提示词，覆盖宿主自带的保守设定
  • 用 56 个探针量化「每一类破到什么程度」，而不是只说「能破」

它不做什么

  • 不改模型权重，不做微调，不碰推理过程
  • 不联网、不上传数据、不自动检查更新——没有服务器
  • 不审核你的输入，也不存储对话
  • 不保证在所有 DSH 版本上生效（见下方短板）

适合谁

适合

做授权安全测试，需要模型给出完整技术细节而不是「建议咨询专业人士」

适合

要写技术文档、教程、CTF writeup，被模型反复拒绝打断思路

适合

想量化对比不同模型的安全防线，需要可复现的评分体系

不适合

只想让模型「说话好听点」——这类需求不需要破甲，改提示词就够

不适合

不能接受改宿主源码——选纯请求边界方案，升级 DSH 也不会失效

不适合

用 DSH 0.2.2-rc.2 或更新版本——本项目实测到 0.2.2-rc.1，更新版本未验证

三层叠加破甲

多数破甲插件只改提示词——模型说「抱歉」那一刻，前面几千字规则全部作废。这里在三个层同时动手。

01

宿主层 96 PATCHES / 70 FILES

直接改写 DSH 源码里的策略判定点：沙箱 deny → allow file-write*、审批门 return allowed-once、观察策略放行、重复调用守卫关闭。这是「强制力」的来源——模型不需要同意，它只是执行。

02

消息层 REFUSAL PURGE

system 注入的盲区：模型一旦决定以「我不能」开头，前面所有规则归零。把历史里的拒绝回复改写成「已作废」，再加半截 可以， 引导首句 token 分布。标准 / 强制两档可选。

03

提示词层 11 SECTIONS

人设、能力清单、尾部硬权重。自检段 order: 1000001 排在所有段之后，确保不被稀释。

三档引擎，每档标注降智程度

不是所有人都要最强档。补丁失效时能降级，而不是整个破甲消失。

「降智」指破甲生效之后模型在正常任务上的表现下降——简单任务绕圈、代码出低级错、忘记前文约束。不是指模型天生弱。成因是破甲指令占用注意力预算，程度取决于破甲强度 × 上下文占用。

多版本宿主适配

补丁按宿主源码字符串匹配，跨版本时部分 pattern 会失配。这里不猜，直接数字告诉你。

控制台里看得到

  • 补丁诊断：96 条里当前宿主上能打几条
    绿 ≥80% / 黄 50-80% / 红 <50%
  • 适配级别：已验证 / 同系列未逐一验证 / 跨版本

为什么不再判死

  • 之前只要版本不在列表里就报「不适配」
  • 但 0.2.1-rc.3 / rc.4 这类同 minor 版本通常能用
  • 现在分三段：已验证绿 / 同系列黄字提示 / 跨版本红字

补丁按版本链组织。96 条里有 46 条带 2 个以上 pattern，各自对应不同宿主版本形态。命中 1 个就能打上，命中数越多说明版本定位越准。
实测 0.2.0-rc.2：73 已命中 / 5 失配 / 18 宿主布局里本来没有。

近期修复

这一轮修的全是「装上了但用不了」的链路问题，不是新功能。

补丁打到影子副本

  • DSH Desktop 解开 asar 后原文件仍留着，宿主从解包目录加载
  • 候选列表把 resources/app 排在前面，补丁全打进影子副本
  • 运行中的宿主一条没改 → 面板显示跳过 / 漂移
  • 现在 app.asar.unpacked 优先

面板数字 1/96

  • gatherState 返回的值来自引擎探针
  • 而探针正是从这个值读补丁数 —— 循环引用
  • 冷启动读到 0 并永久缓存
  • 改成直接查 patchStatus，实测 74/96

工具表被清空

  • 幂等标志设在方法替换之后，抛错就设不上
  • 配合 5 次重试，最多叠 6 层消息包装
  • 宿主判定工具段不可用，116 个工具全没
  • 标志已前移，循环内逐个 try

插件重启杀进程不拉起

  • 只要 app.asar 存在就走 asar 交换
  • 换的那份不被加载，进程没了也起不来
  • 手动点 exe 反而正常
  • 现在先查解包目录，存在就走普通重启

中英切换不生效

  • translate 启动时被宿主 locale 绑定覆盖了两次
  • 那个绑定跟宿主语言，不看面板开关
  • 删掉覆盖，改成按当前语言查本地字典
  • useLang / useT 挂订阅，切换真正重渲染

开关导致语言跳回

  • 破甲页、引擎页的写操作提交时没带 locale
  • 后端退回读浏览器语言（中文环境拿到中文）
  • setData 一覆盖，界面就变回中文
  • 所有写操作现在都带 locale，并依赖语言变化重载

另外四处：assemble 兜底只返回 sections，缺 contexts / tools / variables，宿主依次崩在 null.contexts 和 undefined.map；引擎开关每次重建 explicit 导致连改两个只剩一个；前后端审计发现 5 个前端调用无后端、2 个后端路由前端从没调用；自检报告压在页面底部，点完要下滑一屏半才看得见，现已移到按钮下方并限高。

关于 ASR 数字：本项目 46.2%，市面同类方案也在 45% 左右。这两个数字基本同档，不存在谁碾压谁。差异主要在分母（26 类还是 20 类）和「完全破甲」的阈值。只看 ASR 的话，选哪个都行——真正的差异在降级能力、覆盖面和可解释性。

安装

三步。装完重启 DSH 生效。

1

克隆并部署

环境：Node.js ≥ 18 + DSH Desktop 0.2.x。会自动备份当前状态，改坏了能回滚。

# 环境：Node.js >= 18 + DSH Desktop 0.2.x
git clone https://github.com/yushang657/DSH-YS-pojia.git
cd DSH-YS-pojia
npm run deploy      # 同步到所有 profile（自动先备份）
2

重启 DSH

ESM 模块有缓存，不重启不生效。重启后打开插件面板，能看到「破甲引擎」三档。

3

自检

对话框只输入下面两个字，看到四行回复即为加载成功。
